# 01 PRD：智能面试准备平台

## 1. 文档目的

本文档定义项目的产品边界、核心用户、功能范围、非目标、阶段规划和验收方向。  
它用于约束后续设计、开发和 Claude Code 协同实现。

---

# 2. 产品背景

求职者在准备面试时通常面临三类问题：

1. **知识准备割裂**
   - 技术八股、项目讲解、工程经验、AI 应用知识分散。
   - 普通问答机器人无法保证内容和面试场景强相关。

2. **简历无法映射真实面试追问**
   - 求职者知道简历写了什么，但不知道面试官会如何深挖。
   - 常见“简历优化工具”更多关注措辞，而非面试追问链条。

3. **最新面经信息碎片化且质量参差**
   - 牛客、小红书、抖音存在大量最新面经。
   - 用户很难判断哪些内容是实战经验，哪些是卖课营销或泛化模板。
   - 视频类面经难以直接搜索和归纳。

---

# 3. 产品定位

## 3.1 一句话定位

一个面向求职者的智能面试准备平台，提供：

- 面试知识库问答；
- 简历驱动的个性化模拟面试；
- 管理员驱动的多源面经采集、审核、发布与用户查询。

## 3.2 产品核心差异点

与普通 RAG 聊天机器人相比：

- 聚焦面试场景；
- 支持简历驱动的追问生成；
- 有内容采集与正式面经库沉淀机制；
- 支持图文与视频内容解析；
- 提供可信度评分与内容审核。

---

# 4. 用户角色

## 4.1 普通用户

目标：

- 查面试知识；
- 根据自己的简历准备面试；
- 查询系统已沉淀的最新面经；
- 了解某公司、某岗位近期高频问题。

权限：

- 注册 / 登录；
- 使用知识库问答；
- 上传和分析自己的简历；
- 查询正式面经库；
- 查看自己的历史记录和收藏。

## 4.2 管理员

目标：

- 维护面经内容增长；
- 创建采集任务；
- 查看内容解析结果；
- 审核和发布候选内容；
- 维护正式面经库。

权限：

- 普通用户全部权限；
- 创建内容采集计划或即时采集任务；
- 查看任务执行状态；
- 查看 Raw / Candidate / Published 三层内容；
- 发布、拒绝、下架面经；
- 触发重新解析、重新评分、重新索引等操作。

# 5. 核心功能模块

## 5.1 模块 A：用户系统

### 功能

- 注册
- 登录
- JWT 鉴权
- 获取当前用户信息
- 角色区分：USER / ADMIN
- 用户历史记录基础能力

### MVP 范围

- 邮箱或用户名 + 密码注册
- 密码哈希存储
- 登录获取 access token
- 管理员账号通过 seed 或手工脚本创建

---

## 5.2 模块 B：面试知识库问答

### 用户目标

- 查某个知识点；
- 查某种问题如何回答；
- 获取有引用来源的面试知识答案。

### 示例问题

- RAG 里 rerank 的作用是什么？
- Agent 和 Workflow 有什么区别？
- Redis 为什么快？
- 我的项目中 LangSmith 评估怎么讲？
- Java 中 static 和 final 分别是什么？

### 功能

- 提问
- 检索知识库
- 生成答案
- 展示引用片段
- 流式输出
- 保存会话与消息
- 可查看历史会话

### 数据来源

- 手工整理的 Markdown / PDF / 文档
- 后续可支持批量导入

---

## 5.3 模块 C：简历驱动的模拟面试

### 用户目标

- 上传简历；
- 识别面试官最可能深挖的点；
- 得到问题、回答要点、参考答案和继续追问。

### 流程

```text
上传简历
  -> 文本解析
  -> 简历结构化
  -> 技能/项目/经历识别
  -> 面试追问点分析
  -> 问题生成
  -> 回答要点和参考答案生成
  -> 报告保存与展示
```

### 输出内容

- 简历摘要
- 技能栈识别
- 项目级追问问题
- 技术深挖问题
- 工程设计问题
- 项目真实性问题
- 可能弱点
- 每题参考答案
- 每题继续追问建议

### 约束

- 仅服务当前用户；
- 不将用户简历进入公共内容库；
- 原始简历和分析报告需有权限隔离。

---

## 5.4 模块 D：管理员触发的近期面经更新与整理 Agent 工作流（Phase 4）

> Phase 4 重新定义。核心：管理员创建更新任务 → SearXNG 搜索 → Agent 抽取/路由/评分 → 审核 → 可配置入库 → 用户查询。

### 5.4.1 核心原则

- 不使用付费搜索 API；
- 第一版使用真实数据，不使用 Mock；
- 默认 SearchProvider 为自托管 SearXNG；
- 默认 ContentFetcher 为 httpx + trafilatura；
- Extraction/Routing/Reliability 三 Agent 为核心；
- 默认人工审核，可配置自动审核；
- 默认用户端只展示总结+题目+可信度+原帖 URL；
- 默认不写入 Milvus，可配置开启；
- 默认简历模拟面试不使用面经题库，可配置开启。

- 管理员触发采集；
- 普通用户只查已发布内容；
- 采集内容不一定进入向量库；
- 只有正式发布的内容才进入用户检索库和 Milvus。

### 5.4.2 管理员采集

管理员配置：

- 关键词
- 来源平台：
  - 牛客
  - 小红书
  - 抖音
- 采集数量
- 是否下载图片
- 是否下载视频
- 是否执行 OCR
- 是否执行 ASR
- 是否执行 LLM 抽取
- 是否仅进入候选池

### 5.4.3 后台处理流程

```text
创建任务
  -> 内容发现
  -> 抓取/下载
  -> 原始数据保存
  -> 文本解析
  -> OCR / ASR
  -> 内容融合
  -> 结构化抽取
  -> 规则 + AI 评分
  -> 去重
  -> 候选池
  -> 管理员审核
  -> 发布到正式库
  -> 向量索引入 Milvus
```

### 5.4.4 普通用户查询

用户可查：

- 某公司某岗位最近问什么；
- 某岗位高频问题；
- 某技术话题在哪些面经出现；
- 按来源平台、时间、可信度筛选；
- 查看可信度解释和代表性来源。

用户不可做：

- 实时触发平台采集；
- 查看未发布候选内容；
- 查看原始下载视频文件（除非后续单独设计）。

# 6. 三层内容池

## 6.1 Raw Content Pool

保存：

- 原始 HTML / JSON / 文本
- 原始图片
- 原始视频
- 原始音频
- 原始元数据

存储：

- PostgreSQL：元数据
- MinIO：文件

用户可见：否  
是否入 Milvus：否

---

## 6.2 Candidate Experience Pool

保存：

- 解析正文
- OCR 文本
- ASR 转写
- 融合文本
- 结构化抽取结果
- 评分结果
- 去重信息
- 审核状态

用户可见：否  
是否入 Milvus：默认否

---

## 6.3 Published Experience Library

保存：

- 正式面经记录
- 结构化问题
- 评分与解释
- 展示摘要
- 检索向量

用户可见：是  
是否入 Milvus：是

# 8. 非目标

第一阶段不做：

- 实时语音模拟面试
- 摄像头面试表现分析
- 自动岗位推荐
- 简历投递追踪
- 招聘 CRM
- 全站商业级内容运营
- 全量历史面经爬取
- 多租户组织权限系统

# 9. 关键用户故事

## 9.1 普通用户故事

1. 我可以注册登录后进入系统。
2. 我可以问一个技术面试问题并获得引用知识库的回答。
3. 我可以上传自己的简历并得到针对性面试题。
4. 我可以查询“最近字节大模型应用岗问什么”。
5. 我可以看到系统整理出的高频问题、来源和可信度说明。

## 9.2 管理员故事

1. 我可以创建一个“字节大模型应用岗面经采集”任务。
2. 我可以选择采集牛客、小红书、抖音中的某几个来源。
3. 我可以查看任务是否成功、失败在哪一步。
4. 我可以查看某条候选面经的原始内容、解析内容和 AI 抽取结果。
5. 我可以将高质量内容发布到正式面经库。
6. 发布后普通用户可以检索到这些内容。

# 10. 核心验收标准

## 10.1 产品边界验收

- 普通用户查询面经不会触发爬虫；
- 未发布候选内容不会进入用户搜索结果；
- 未发布内容不会进入 Milvus；
- 管理员与普通用户权限明确。

## 10.2 功能验收

- 登录注册可用；
- RAG 问答可用；
- 简历分析可用；
- 管理员采集任务框架可用；
- 发布流程跑通；
- 用户能查已发布面经。

## 10.3 工程验收

- Docker 基础设施可启动；
- 后端使用统一依赖管理；
- 前后端目录清晰；
- Worker 流程明确；
- 数据库迁移可执行；
- 文档与代码一致。

---

# 11. 产品成功指标建议

早期可关注：

- 知识问答检索命中率；
- 简历分析报告完成率；
- 管理员采集任务成功率；
- Candidate -> Published 的内容转化率；
- 用户面经查询命中率；
- 发布面经的检索点击率；
- 可信度评分与人工判断的一致性。
