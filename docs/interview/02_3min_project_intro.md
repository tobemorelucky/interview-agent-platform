# 3 分钟项目介绍

下面是口语稿，不需要报类名。按自己的语速删减，优先讲清事实层、状态层、记忆层三个边界。

## 口语稿

**背景。** 我做的是一个面向秋招的多 Agent 求职与模拟面试平台。准备面试时，简历、岗位要求、项目回答和复盘往往是分开的。我希望把它们串起来，但又不希望模型凭感觉判断“你会什么”，或者聊着聊着把面试状态推进错。

**架构。** 系统有公共数据和用户私有数据两条边界。公共岗位、JD、面经经过采集或人工来源导入、证据抽取和审核；用户侧是简历、候选人画像、面试和记忆。六个正式 Agent 分别处理研究、画像、匹配、提问、评价和复盘。模型负责生成与分析，程序负责证据、资格、状态、预算、版本和幂等。业务数据主要落 PostgreSQL，耗时的简历处理交给 Worker。

**Profile。** 这里我做过一个比较关键的改造。最初让模型生成事实文本，再引用简历证据；真实简历测试发现，自由改写容易和严格的字面支持规则冲突。最终改成模型选择和分类已有 Evidence，程序还原引用、验证标签，并直接用真实证据生成兼容的事实描述。技能只用有限证据状态，而且只能向下收敛。摘要和优势不进入稳定事实层；用户修正产生完整新版本，旧版本不覆盖。

**Matching。** 岗位匹配先由程序筛选、判断硬资格并建立 Evidence Matrix，再让模型在允许的候选中做排序和解释。材料缺少证明就是“没有证据”，不是“不会”。学历、专业等缺少可靠结构化字段时保留 UNKNOWN，不让模型猜满足。结果保存输入版本和三层排序，也不展示看似精确的匹配百分比。

**Interview。** 每场面试固定 Profile、JD、题目内容和已批准记忆快照。提问 Agent 与评价 Agent 分离，评价只描述这次回答；是否追问、深挖、下一题或结束，由确定性 Controller 校验。回答有幂等键，模型调用不占数据库长事务。真实测试还修过首题误结束和浏览器断连后评价卡住的问题，现在失败有审计，同一回答可以安全重试，刷新也会读取持久化状态。

**Memory。** 复盘报告中的统计由有效 Evaluation 计算，Coach 只做解释。面试观察不等于长期能力事实，记忆建议默认待审批；用户批准或修正后才进入已有 Memory 系统。下一场一次性读取并固定，已经开始的面试不会因为后来批准记忆而漂移。

**验收。** 项目经历过真实 PDF、真实公开 JD、真实模型和浏览器测试，不只是 Demo。最近一场真实模型六轮面试完成了六组回答和评价，也验证过报告、记忆批准和下一场快照读取。但它仍是个人本地项目，首次匹配和评价有模型延迟，硬资格覆盖有限，Live Search 冻结。我不会把这些说成生产规模或稳定低延迟服务。

## 面试时的取舍

- 时间不够：省略中间件名字，保留“证据选择、Controller、受控记忆”。
- 对方关注 AI 应用：展开 Structured Output 与业务 validator 为什么是两层。
- 对方关注银行科技：展开事务、历史快照、权限、失败恢复与审计。
- 被问性能：报告具体场次和模型，不把一次测量包装成平均 SLA。
