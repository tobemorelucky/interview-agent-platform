# 简历项目描述

项目名称：**面向秋招的 Multi-Agent 求职与模拟面试平台**。

项目性质：个人项目，本地运行与真实模型验收；不写“已服务大量用户”或“生产上线”。以下表达适用于你能实际讲清并承担的工作，不能把工具辅助完成的部分说成独立完成的每一行代码。

## 版本一：AI 应用开发岗

- 搭建研究、画像、匹配、面试、评价、复盘六角色链路，将模型生成与确定性业务控制分离，避免模型直接决定资格、状态、预算或长期用户事实。
- 将简历画像从自由事实生成改为 **Evidence Selection**：模型选择原始证据，程序精确还原引用、验证标签并建立规范化事实与版本，减少自然语言改写与严格 grounding contract 的冲突。
- 实现 **Evidence Matrix + 硬资格判断** 的岗位匹配流程，在程序筛选后进行模型 rerank，保留材料缺口与 UNKNOWN，使用解释性等级而非虚假匹配百分比。
- 构建固定上下文、提问/评价分离的模拟面试流程，通过 Controller、幂等回答与短事务版本校验管理追问、深挖和切题，并修复预算误结束、浏览器取消后的恢复问题。
- 打通报告、表现观察与受控记忆建议；统计由数据库有效评价计算，记忆仅在用户审批后进入下一场快照，并通过真实 PDF、JD、模型和浏览器记录验证关键链路。

## 版本二：银行 / 央国企科技岗

- 将求职准备组织为简历画像、岗位匹配、模拟面试、复盘和成长记录闭环，采用模块化 API 与独立 Worker，区分公共职业资料和用户私有数据，明确查询与离线入库边界。
- 建立可追溯的简历事实与版本管理：事实关联原始证据，修正生成完整新快照，事务内最后切换当前版本，防止历史被覆盖或当前版本指向半成品。
- 设计岗位硬资格与技术匹配分层机制，硬条件由程序判断，材料不足保留未知；匹配保存输入快照和排序依据，支持历史解释与一致输入的成功结果复用。
- 为面试回答和评价增加幂等、乐观版本校验及取消恢复，模型调用期间不持有数据库长事务，避免重试重复落库或网络中断留下永久处理中状态。
- 实现报告当前版本原子切换和记忆审批事务，将批准内容、用户确认事件与建议状态一起提交；保留失败记录，保证自动分析不会直接改写长期事实。

## 最建议优先保留的三条

1. **画像 Evidence Selection**：同时体现 AI contract 设计、事实来源和真实排障，不只是调用模型接口。
2. **确定性面试控制与安全恢复**：能展开事务、并发、预算、SSE、取消和幂等，工程深度最强。
3. **Evidence Matrix + eligibility**：有明确产品取舍，能说明“没有证明”与“不满足”的区别。

## 可以讲的量化事实

仅在被问到、并带上条件时使用：

- 最新记录是后端 **340 passed**、前端 **31/31**，不是本次材料整理重新跑出的结果。
- 一个真实六轮 Doubao 2.1 场次，6 个唯一 Answer 对应 6 个有效 Evaluation；该场 Main 平均 8.25 秒，Evaluation 平均 24.63 秒。这是小样本调用延迟，不是 SLA。
- 真实 Resume 38 的旧请求 14620 字符，首次 context 修复后 9707 字符；保留 40 条原子证据与 1450 字符 excerpt。只能说请求体积变化，不能推出推理速度提升百分比。

## 不建议写进简历 / 面试

- 高并发、QPS、用户量、商业收入、线上可用率：没有相应生产验证依据。
- “完全消除幻觉”“保证资格正确”“真人级面试官”：现有校验不能证明这些绝对结论。
- “公网自动补库稳定运行”：Live Search 冻结，人工真实来源导入不是实时搜索。
- “全球分布式限流”“Exactly-once Celery”：当前没有这样的保证。
- “模型延迟降低 X%”：模型、输入与场景变化，不能把不同请求直接当受控性能实验。
