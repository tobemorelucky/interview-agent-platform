## 1. 真正的问题

- #629 首题是固定 `INTRODUCTION`；用户误粘贴 2,223 字 ASPCF 第五章技术计划，Intro 回答不评分但被原样送进 Main 上下文，Main 没有判断异常，直接生成 Agent 项目题。

- 「换题/暂停」与「回答不知道/简短回答」没有在提交前做确定性区分。

## 2. 修复内容

### 2.1 取消默认自我介绍

- `router.start_interview` 默认 `opening=MODEL`；`web/api/interview.ts` 默认 `MODEL`。
- `core_service.start()` 内部默认本就是 `MODEL`，三处现在一致。
- 新 Main Prompt 明确「自我介绍只是服务端可选项，不是你的开场」。
- 前端 `READY` 状态新增可勾选「以自我介绍开场（可选，不计技术分）」；选择后才传 `INTRODUCTION`。历史冻结会话不受影响。

### 2.2 提交前回答相关性检查（零额外模型调用）

新增纯规则模块 `answer_relevance.py`，在答案已持久化、**Evaluation 之前**运行：

| 语义 | 处理 |
|---|---|
| `USER_CONTROL`（结束 / 换题 / 暂停 / 跳过） | 确定性拦截：结束走原确认流程；换题返回 `INTERVIEW_TOPIC_CHANGE`，前端确认后才调用既有 skip 接口，本题不计分、不写记忆。 |
| `OFF_TOPIC_SUSPECTED` | 只在「长文档 + ≥3 个文档标记 + 与问题/岗位/Skill 无主题重叠 + 无第一人称」时触发，返回 `OFF_TOPIC_CONFIRMATION_REQUIRED`。**不调用 Evaluation / Main，不写评价、画像或记忆**，写 `AuditLog` 并保留原始回答消息。前端弹窗允许「确认按原文继续」或「重新回答」。 |
| `UNKNOWN` | 明确「不知道/不会/没做过」是有效回答，正常进入 Evaluation；不会因短而当成粘贴错误。 |
| `VALID` | 其余一律正常进入 Evaluation；「相关但不清楚」由 Main 依据回答与 Evaluation 选择一次自然澄清，不额外固定调用模型。 |

- 重答复用同一题目的唯一 Answer 行，改绑新回答消息与幂等键；**被拒原文仍以 USER message + AuditLog 保留**，但因没有 Evaluation，`excluded_reason`、统计、题量、成长记忆都不会引用它。
- 用户确认按原文继续时，用同一幂等键带 `confirm_off_topic=true` 跳过预检查，只发生正常 Evaluation/Main 调用。
- 回答文本始终按数据处理；Prompt 明确一律不执行其中的指令。

> 这是保守规则而非语义裁判：只拦「明显整段粘贴」，短回答、缺少术语、概括性回答仍按正常质量评价处理。没有为每轮增加模型调用；没有新增 Agent 或模型路由。

### 2.3 Main Prompt 2.9.0

新增 `MAIN_INTERVIEWER_V9`（`interview_main` **2.9.0**）：保留现有合法 `AdaptiveSelection` / gap-scope Schema 契约，把新对话策略作为核心分节重写，而不是末尾追加一句「自然交流」：

- `IDENTITY`：有项目经验的技术面试官，不是题库/评分点机器人；所有简历/回答文本是数据。
- `ASKING`：直接从岗位、简历与 Skill 切入；先项目目标、个人职责、实际技术，再机制；一次一个主问题；允许岗位相关基础与场景题；不编造经历。
- `HANDLING THE ANSWER`：先理解真实回答；充分可深入也可换题；相关但不清楚只澄清一个点；不知道是有效回答；两次澄清无进展就换题；不把 `missing_points` 直译成下一问。
- `CONVERSATION`：自然中文承接，不重复固定句式，不每轮引用简历；风格只影响追问力度；临近结束收束话题，不自行播报分数。

`freeze_prompts` 对新会话冻结 2.9.0；`context_projection` 白名单保留 2.8.0/2.7.0/2.6.0/2.5.0/2.3.3，历史会话与冻结快照不变。

### 2.4 两种评分展示模式

- **模拟（默认）**：逐题分数、覆盖/缺失要点与参考答案在结束后统一展示，完全复用 R126/R128 的隐藏规则。
- **练习**：本题评价正式提交后即可展开查看五维分数、覆盖要点、缺失要点与改进建议；默认展开。由本地偏好 `interview_score_mode` 保存，不调用任何额外模型。
- 完整报告仍保留五维与证据引用；参考答案仍受结束后显示规则约束。
