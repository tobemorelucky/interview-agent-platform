## 为什么不直接给 50 份完整原文？
当前检索已经核实了部分官方网站职位内容，但工作环境不能直接向外部招聘网页下载原始 HTML 到文件，网页搜索结果的局部文字也不能充作完整逐字原文。不能凭标题和常见技术栈编造岗位，或未经校验把摘要导入 Evidence 正式表。

## 本地使用
1. `python 05_导入本地SQLite待审表.py --out review_staging.sqlite3` — 仅导入 staging 数据。
2. 先在能够访问招聘页面的本地执行：`python 04_本地抓取官方原文_不自动入业务表.py --mode browser`。需要本地安装 Playwright 并安装 Chromium。无浏览器环境可用 `--mode stdlib`，但 JS 页面可能无法取得正文。**抓取结果仍需逐条核实并去除页面导航**。
3. 可以先执行 `python 06_从官网列表发现更多真实岗位.py` 从沐瞳/蔚来官方列表发现新详情页网址（需逐条抓取、去重、校验原文；部分网站分页无法抓到时需要人工操作）。50 份目标：官方招聘索引还可从 `https://moonton.jobs.feishu.cn/campus/position/list`（约 92 个岗位）与 `https://www.kylinos.cn/about/job/campusRecruitment/`（多个职位）、蔚来校招岗位页继续发现。新增岗位应有唯一来源 ID、职责、任职要求、正文 SHA256、抓取日期。不得虚构、重复计算或跳过站点规则。
4. 校验后交由 WorkBuddy 用项目**现有合法 Research / Owner / Evidence**流程导入独立沙箱业务表。凡要进行真实 LLM 调用的步骤先申请 HTTP/Token 预算。不要直接 SQL 插入正式业务表、不要修改受保护数据、不要把人工整理题库当成历史真实面试 Session。
5. 单独跑独立的模拟用户和合成简历流程，真实简历接入放在数据集通过后。

## 来源与真实性口径
- 岗位页面来自企业官网，具有来源网址和可检索岗位信息；**未保存原始逐字全文，暂时不得标为 VERIFIED_JD_FULLTEXT**。
- 面经是牛客用户公开帖子自述，面试日期与企业/岗位是**发帖者声明**；题干为根据帖子改写，不能伪装成真实录音逐字题目。
- 本包没有任何企业来源编造的职位，也没有把此前 50 条合成 JD 混入真实计数。
- 原始职位全文与帖子全文归各自网站/作者所有。请保留来源，并按网页使用条款进行测试和存档。
