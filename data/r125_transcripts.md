### Java 后端：项目经历充分，结合项目深入后换题

**面试官（开场）**：你简历里那个订单秒杀系统，聊聊你负责的那部分吧，库存这块是怎么扛住并发的？

**候选人**：库存我用了 Redis 的 Lua 脚本做原子扣减，前面还有一层预校验，热点商品会先预热到本地缓存。

**面试官（新题）**：你刚提到用 Kafka 削峰，那重复消费这块你们是怎么处理的？

**候选人**：重复消费我们用订单号做幂等键，先在去重表里插一条，唯一索引冲突就直接跳过。

**面试官（追问）**：幂等这块再确认一下：如果消费成功、但下游事务还没提交就挂了，会怎样？

**候选人**：消费成功但事务没提交就挂了的话，消息会重投，重投时去重表已经有记录了，就会跳过，这块其实有漏的风险，我们后面加了状态机。

**面试官（新题）**：去重表本身也会成为热点，你们怎么避免它变成瓶颈？

**候选人**：去重表按订单号哈希分片，热点订单会单独走一个本地缓存加短锁，批量的走异步。

**面试官（新题）**：换个话题。你们 MySQL 的慢查询，一般怎么定位到具体是哪条 SQL？

**候选人**：慢查询先看 slow log，按执行时间和扫描行数排序，再用 explain 看是不是走了索引，最后结合业务看能不能改 SQL 或者加联合索引。
